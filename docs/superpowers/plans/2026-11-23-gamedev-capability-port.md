# 游戏开发验证能力移植计划

## 方案

参考本地 `awesome-gamedev-agent-skills` 的 `c6ca6c4`，保留 UnityRunBridge 的 CLI / JSON / Editor Bridge 分层与 Unity 2022.3 最低版本。工具只读分析；不引入其他引擎或上游统一 Router，不修改参考仓库，不推送。复用上游源码时记录来源、修改和 Apache-2.0 许可。优先用现有命令和归档产物组合，不用文档宣称运行时尚无的能力。

## 开发任务（依次实施）

- [x] **1. 离线健康检查**：将上游 .meta/GUID、文本脚本引用检查适配到 `health`；保留在线检查，清楚区分已确认问题、待 Unity 导入以及未验证（包、二进制、DLL 等）。验证无 Editor、只读、机器可读与退出码，覆盖正常及常见误报。
- [ ] **2. 构建体积诊断**：适配上游构建日志解析和资源扫描；复用本项目归档的 `build.log` / `build-report.json`，分别提供未压缩报告、实际交付产物大小、静态线索；支持明确口径的预算检查，数据缺失不得判为通过。覆盖多次构建记录、缺失/截断、纹理/音频/StreamingAssets/glTFast。
- [ ] **3. 性能回归**：以固定场景/输入/窗口和基线为前提，用现有 `profile`、`scenario` 的指标断言交付可校验示例和证据判读；区分 Editor 与 Player/GPU 结论，检查指标不可用和中断边界。
- [ ] **4. UI 回归**：用现有 Scenario、截图、UGUI 和项目侧白名单观测交付可复跑示例，覆盖弹窗默认焦点与关闭恢复，以及多尺寸截图检查工作流；本次不冒充已有视觉差分，明确可自动与人工验收项。
- [ ] **5. Skill 触发评测**：为两个发布 Skill 增加中文/英文正例、近似反例、组合和不触发样本；本地校验资产和评测数据，提供可重复执行、独立于格式校验的判分流程，不使用全引擎 Router。

## 验证、审查与提交

每项先写回归测试（适用时确认旧实现失败），实现后跑针对性测试与 Python 回归，再审查与测试覆盖、边界、兼容性和授权范围；发现问题先修复并复测。Unity 运行态工作流优先使用本机 2022.3；不能验证的项目明确记录实际原因，不用静态校验当运行验证。审查通过后仅暂存该项文件并单独本地提交，再进入下一项。计划调整及原因写在此处，最终按五项与提交记录逐一审计。

### 任务 1 审查记录

- 不采用上游「同目录同扩展名即推断移动」的失败规则：删除一个旧文件后新增同类文件也会命中。报告孤立/缺少 `.meta`，只有实际冲突、无效 GUID 或覆盖充分时找不到标准脚本 GUID 才判失败。
- 不接受任意同名包缓存：同名旧版本、与 manifest 不一致的旧 Git 锁定项不能充当已解析证据。未知包、链接或读取不全影响结论时只报未确认；按行有界扫描，不一次读取大型 YAML 数据行。
- 定向测试 38 通过；完整 Python 回归 352 通过（需本机 loopback 权限）；临时目录构建 wheel 核实扫描模块及 Apache-2.0 LICENSE / NOTICE 均在包内。
