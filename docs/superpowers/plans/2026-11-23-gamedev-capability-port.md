# 游戏开发验证能力移植计划

## 方案

参考本地 `awesome-gamedev-agent-skills` 的 `c6ca6c4`，保留 UnityRunBridge 的 CLI / JSON / Editor Bridge 分层与 Unity 2022.3 最低版本。工具只读分析；不引入其他引擎或上游统一 Router，不修改参考仓库，不推送。复用上游源码时记录来源、修改和 Apache-2.0 许可。优先用现有命令和归档产物组合，不用文档宣称运行时尚无的能力。

## 开发任务（依次实施）

- [x] **1. 离线健康检查**：将上游 .meta/GUID、文本脚本引用检查适配到 `health`；保留在线检查，清楚区分已确认问题、待 Unity 导入以及未验证（包、二进制、DLL 等）。验证无 Editor、只读、机器可读与退出码，覆盖正常及常见误报。
- [x] **2. 构建体积诊断**：适配上游构建日志解析和资源扫描；复用本项目归档的 `build.log` / `build-report.json`，分别提供未压缩报告、实际交付产物大小、静态线索；支持明确口径的预算检查，数据缺失不得判为通过。覆盖多次构建记录、缺失/截断、纹理/音频/StreamingAssets/glTFast。
- [x] **3. 性能回归**：以固定场景/输入/窗口和基线为前提，用现有 `profile`、`scenario` 的指标断言交付可校验示例和证据判读；区分 Editor 与 Player/GPU 结论，检查指标不可用和中断边界。
- [x] **4. UI 回归**：用现有 Scenario、截图、UGUI 和项目侧白名单观测交付可复跑示例，覆盖弹窗默认焦点与关闭恢复，以及多尺寸截图检查工作流；本次不冒充已有视觉差分，明确可自动与人工验收项。
- [x] **5. Skill 触发评测**：为两个发布 Skill 增加中文/英文正例、近似反例、组合和不触发样本；本地校验资产和评测数据，提供可重复执行、独立于格式校验的判分流程，不使用全引擎 Router。

## 验证、审查与提交

每项先写回归测试（适用时确认旧实现失败），实现后跑针对性测试与 Python 回归，再审查与测试覆盖、边界、兼容性和授权范围；发现问题先修复并复测。Unity 运行态工作流优先使用本机 2022.3；不能验证的项目明确记录实际原因，不用静态校验当运行验证。审查通过后仅暂存该项文件并单独本地提交，再进入下一项。计划调整及原因写在此处，最终按五项与提交记录逐一审计。

### 任务 1 审查记录

- 不采用上游「同目录同扩展名即推断移动」的失败规则：删除一个旧文件后新增同类文件也会命中。报告孤立/缺少 `.meta`，只有实际冲突、无效 GUID 或覆盖充分时找不到标准脚本 GUID 才判失败。
- 不接受任意同名包缓存：同名旧版本、与 manifest 不一致的旧 Git 锁定项不能充当已解析证据。未知包、链接或读取不全影响结论时只报未确认；按行有界扫描，不一次读取大型 YAML 数据行。
- 定向测试 38 通过；完整 Python 回归 352 通过（需本机 loopback 权限）；临时目录构建 wheel 核实扫描模块及 Apache-2.0 LICENSE / NOTICE 均在包内。

### 任务 2 审查记录

- 真实 Unity 2022.3.62f2 增量构建成功但日志没有资源成本，预算必须是 `unverified`。因此调整方案，为 `build` 增加显式 `--clean`（Unity `BuildOptions.CleanBuildCache`），默认仍走增量。实际 macOS clean 构建解析 10 个分类、202 条资源；未压缩日志值 103389594 字节，交付目录实测 103352590 字节。预算放宽时分别通过，日志预算收紧时失败，交付预算保持独立。
- 审查修正旧/截断日志回退、复制的归档误读旧绝对输出路径、缺文件被另一个有效输入掩盖、软链接被当作普通文件。静态扫描不提供自动改写命令；有界读取并报告未知导入设置和格式，不能用于预算。
- 定向构建测试 33 通过、完整 Python 回归 369 通过、真实 macOS Player clean build 成功、Unity BuildRunner EditMode 4 通过。静态资源种类采用合成 fixture 与真实项目只读扫描验证；没有在 Android/iOS/WebGL 上执行构建。

### 任务 3 审查记录

- Unity 2022.3.62f2 实测无图形 Editor 能创建 recorder 但没有真实数据，旧的占位值 0 曾错误通过预算。经审查改为跳过无样本计数器，Scenario 拒绝零 CPU 耗时和非有限数；零 GC 分配仍有效。新增 `minSamples`，并明确阻止已中断、未停止或停止失败的数据通过个别断言（即使继续执行）。
- 带图形 Editor 的同场景三轮基线全部通过，得到 432/435/445 条有效样本；人为设置 CPU p95 ≤ 0 的负例失败，无图形模式正确返回 `metric_not_available`。验证中发现 Play Mode 退出后重载会短暂拒绝连接，示例要求每轮确认 idle 后再开下一轮。没有把测试副本数值当成实际项目性能预算。
- Scenario 定向测试 84 通过，完整 Python 380 通过，Unity Profiling EditMode 10 通过；GUI/无图形结果均按 Editor 模式记录，不声称验证了真机、Player 或 GPU。

### 任务 4 审查记录

- Unity 2022.3.62f2 图形 Editor 先证明 `Screen.width/height` 可能读到 Editor 面板尺寸、旧截图会包含工具栏和留白。改为 Canvas 像素探针 + 真实 Game View 渲染纹理，规范化图形 API 的 Y 轴；没有可读纹理时明确失败，不回退到桌面/编辑器窗口。缩放标注和命中统一使用原始 Game View 尺寸；仅允许内建默认无 session 截图走已定义 scratch 根，显式路径仍受原门禁。
- 实跑横屏 1280×720、竖屏 720×1280，读 PNG 头验证四张图，逐图检查 Confirm/Open 焦点样式、方向、文字及无裁切。错误焦点和错误截图尺寸负例都返回失败；实际 640×360 标注图上的坐标反查命中正确 UGUI 控件。
- Scenario 定向测试 96 通过、完整 Python 回归 392 通过、Unity Capture EditMode 18 通过（含 GPU 像素读回及纵向翻转）。实体手柄、异平台/图形 API 和真机安全区未验证；文档明确属于另行验收，不宣称已有视觉差分。

### 任务 5 审查记录

- 语料含 20 道中英双语题（8 正例、4 近似反例、2 组合、6 不触发）。离线检查验证安装后的元数据、相对文档引用、调用权限和语料覆盖。导出只含题目与描述，不给判题方答案或分类标签；评分同时检查漏选、误选、非法自动调用及缺失/重复输入。
- 同一题集独立盲评各一次：旧描述 18/20（漏选构建体积、离线健康两类），新描述 20/20，未新增误选。导出指纹分别为 `080400fce9d80052ac619cfa5a19c89c572b7a3afac181470b234d3ab91807cb` 与 `8e7f9ed6b9f261fd54eb28437cb6870f1ef26353f4a372504442ff7d74aa7a00`。这只是单次盲评，不代表所有宿主上的实际自动触发率。
- Skill 相关测试 22 通过，完整 Python 回归 399 通过。由实际 wheel 解包后执行 `skills init`，验证两份安装产物和全部 20 题；同一 wheel 中验证性能及横竖屏共三份 Scenario，确认许可和相关模块均已打入。
